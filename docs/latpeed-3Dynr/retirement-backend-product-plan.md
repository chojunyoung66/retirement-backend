# retirement-backend 고도화 방안 (3Dynr 참고)

> **성격:** 래피드 3Dynr와의 **협력·공동 제품 계획이 아님**.  
> 시장에 나온 실무 패키지(3Dynr)를 **벤치마크·참고**하여, 자체 시뮬레이터 API를 고도화하기 위한 내부 계획이다.

> 정리일: 2026-07-24

## 왜 참고하는가

3Dynr 핵심 메시지: 은퇴 문제는 **자산 총액**이 아니라, **세금·보험료를 뺀 뒤 매달 얼마가 들어오게 배치·인출하느냐**.

우리 MVP는 개별 시뮬(건보·ISA·IRP 등)과 목표 저장에 강점이 있고,  
**세후 월 CF를 설계 단위로 묶는 레이어**가 상대적으로 약하다.  
→ 그 갭을 메우는 것이 이번 고도화의 초점이다.

## 참고 범위 / 비범위

| 포함 | 제외 |
|------|------|
| 도메인 축·체크리스트·샘플 케이스를 요구사항·테스트 힌트로 사용 | 래피드 판매·정산·콘텐츠 연동 |
| 자체 API·스키마·TDD로 재구현 | 3Dynr 콘텐츠 복제·재판매 |
| “교육·시뮬 수준” 가정과 면책 유지 | 세무·건보 자문 대체 주장 |

## 현재 MVP vs 고도화 목표

| 영역 | 지금 | 고도화 목표 |
|------|------|-------------|
| Auth | JWT 1개 · Bearer | Access + Refresh(HttpOnly) 병행 가능 |
| Goals / Portfolio | 있음 | 세후 CF 관점 필드·결과 확장 |
| Simulations | 건보·국민연금·ISA·IRP·퇴직·실업 | CF 타임라인에 **합류** |
| 세후 월 CF | 약함 | **설계 단위**로 승격 |
| 1,500만 / 인출순서 / 3버킷 | 없음·부분 | Phase B~C |

## 고도화 우선 축 (벤치마크에서 추출)

1. **세후 월 현금흐름** = 생활비 목표가 아닌 설계 단위  
2. **사적연금 연 1,500만** 저율 vs 초과 시 종합/분리(16.5%) 가정  
3. **재원 인출 순서** (미공제 원금 → 이연퇴직 → 공제분·수익)  
4. **국민연금 전/후** (브릿지 vs 조기수령)  
5. **건보·피부양** = 세금과 별도 트랙  
6. **인출률 4~4.5%** 가드레일 + 3버킷(현금·완충·성장)

## 단계별 실행 계획

### Phase A — 요구 정리 (문서·모델)
- 체크리스트/노션 항목 → Prisma·DTO 후보 매핑
- 샘플 3케이스 → golden test fixtures  
  (`Case0_55세_5억` / `Case1_58세_10억` / `Case2_60세_4억`)

### Phase B — 현금흐름 코어
- 세후 월 CF 도메인 (TDD)
- 숨은 지출 + 갭(목표 − 확정성 수입)
- cashflow-plan API (또는 `SimulationType` 확장)

### Phase C — 세금·인출 가정 엔진
- 1,500만 한도 로직 (교육용 가정, 설정 가능하게)
- 인출 순서 + 인출률 가드레일
- 시나리오 비교 (정상개시 vs 조기수령 등)

### Phase D — 기존 시뮬 합류
- health / national-pension 결과를 CF 타임라인에 연결

### Phase E — 인증·보안 (병행 가능)
- Access + Refresh(HttpOnly, Path) + rotation
- CORS FE origin 화이트리스트 + credentials
